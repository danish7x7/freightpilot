`gemini-flash-latest` now resolves to **`gemini-3.6-flash`**. First live demonstration of what the
stamp exists for: the requested `model` field reads `gemini-flash-latest` on all 20, so before the
stamp a rotation left no trace in the bytes at all.

Because the quota wall makes this capture multi-day, a second rotation between sessions would fill
the remaining 23 calls from a different backing model and every existing provenance assertion would
stay green. Added a uniformity assertion to `recordingProvenance.test.ts`: the distinct `servedModel`

The field makes rotation auditable, not self-detecting. Record mode never re-fetches an existing key,
so the enforcement when it goes red is `rm -f` on the recordings and one fresh capture. ADR-0012 §2A.1.

## Correction: a quota wall aborts, it does not churn

Before the run both the implementer and the reviewer said a 429 would be caught per-case by
`scoreCase` and let the run continue through the remaining cases. Wrong, and worth recording because
two people asserted it independently and neither checked. `LlmChainExhaustedError` extends `Error`,
not `LlmError` (`errors.ts:44`), and `scoreCase` rethrows anything that is not an `LlmError`
(`score.ts:73`), so the process exits at the first exhausted call. ADR-0012 §2A.2.

## The 44-vs-43 finding, recorded BEFORE the fix changes it

Budgeted 43 calls: 41 single-call cases, plus 2 for `tools-validation-retry-zero-weight`. The extra
call belongs to **`extraction-missing-destination-clarify`**, which was budgeted at one.

Input: "I want ocean rates out of CNSHA on 2026-08-01." The destination is absent. Recorded call 1:

```
text: null
toolCalls: [ search_rates { mode: OCEAN, origin: CNSHA, ship_date: 2026-08-01 } ]
```

The model called the tool with **no `dest`** rather than asking for it. `searchRatesArgs` requires
`dest`, Zod rejected it, the loop's retry fired, and that second call is where the 400 landed.

This is a behavioral datum about the Lite tier and it is recorded now because the adapter fix will
change what happens after the Zod rejection, not what happens before it. The first call is the datum:
under the v1 prompt, this model answered a missing-field request by guessing a tool call rather than
naming the field. The prompt's clarification rule says to name the field you cannot proceed without.

**One correction to how this was framed.** It is not an easy case. ADR-0012 §2.2 classifies
`extraction-missing-destination-clarify` as **HARD**, one of the 11, as §7's missing-fields coverage,
and §2.2.1 records that exact reclassification. So it sits in the tolerated bucket rather than the
zero-tolerance one. That does not make the datum less interesting; it changes what it costs.

**The floor is not adjusted.** ADR-0012 §2.6 permits two responses to a miss and neither is moving
the number. Whether the retry now succeeds and the case passes, or the model still fails to clarify,
is a measurement to be reported after the re-capture.
