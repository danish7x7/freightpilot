## The alias rotated, and the servedModel stamp caught it

`gemini-flash-latest` now resolves to **`gemini-3.6-flash`**. First live demonstration of what the
stamp exists for: the requested `model` field reads `gemini-flash-latest` on all 20, so before the
stamp a rotation left no trace in the bytes at all.

Because the quota wall makes this capture multi-day, a second rotation between sessions would fill
the remaining 23 calls from a different backing model and every existing provenance assertion would
stay green. Added a uniformity assertion to `recordingProvenance.test.ts`: the distinct `servedModel`
set across non-error recordings must have exactly one member, and the failure names each distinct
value with its recording count. **Mutation: edit one fixture's `servedModel`, test fails** with
`gemini-3.6-flash: 19, gemini-3.7-flash: 1`; restored clean. Runner suite 81 pass / 4 fail, the same
four documented pre-capture reds.

The field makes rotation auditable, not self-detecting. Record mode never re-fetches an existing key,
so the enforcement when it goes red is `rm -f` on the recordings and one fresh capture. ADR-0012 §2A.1.

## Correction: a quota wall aborts, it does not churn

Before the run both the implementer and the reviewer said a 429 would be caught per-case by
`scoreCase` and let the run continue through the remaining cases. Wrong, and worth recording because
two people asserted it independently and neither checked. `LlmChainExhaustedError` extends `Error`,
not `LlmError` (`errors.ts:44`), and `scoreCase` rethrows anything that is not an `LlmError`
(`score.ts:73`), so the process exits at the first exhausted call. ADR-0012 §2A.2.
