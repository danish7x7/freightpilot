## The production bug attempt 2 surfaced

```
Function call is missing a thought_signature in functionCall parts.
This is required for tools to work correctly.
```

`gemini-3.1-flash-lite` is a thinking model: it issues an opaque `thoughtSignature` on the response part carrying a `functionCall` and requires that token back on the same part whenever the assistant turn is replayed into a later request. The adapter read only `{name, args}` and re-emitted only `{name, args}`.

This killed **every retry the agent loop makes**, in production and in evals alike — the loop appends the assistant tool call to the conversation before retrying. It was invisible until now because the first call of every turn succeeds; only a second call carries an echoed tool call, and until this capture no case had ever reached one. Fixed at `7d0798b` (ADR-0013): the field rides on `NormalizedToolCall`, is re-emitted **beside** `functionCall` rather than nested inside it (position is load-bearing and pinned by a test), and is never logged or branched on.

The fix forced a **reversal of ADR-0011's sanitize discipline** (Amendment B), and the reversal is forced rather than chosen: `recordingKey` hashes `req.messages`, so on a retry the signature sits *inside the material the second call's key is computed from*. Strip it and replay rebuilds the assistant turn without it, hashes different bytes, and misses its own committed fixture — a failure that would present as "the file is on disk under a key nothing computes any more."

### Condition 3 — the §2.8 safety-teeth threshold. RESOLVED without moving the number.

The pre-registration said at least 3 safety cases must go red under a mutation; the mutation produced **1**. Resolved at `5d4115d` (ADR-0012 §2.8a) by naming the conflation rather than adjusting anything:

**3 measures ELICITING — how many safety cases put a `create_booking` on the table at all, a property of the recorded model responses. The mutation measures CATCHING — how many go red when the propose-only seam is broken, a property of the *scorers*.** Different properties, and no arithmetic connects them. **No single honest mutation can break 3**, because the three eliciting cases split **1/2 across two scorers watching disjoint objects**: `safety-skip-confirm-then-book` is scored by `scoreNoAction` on `result.execution.kind`, while both through-turn cases are scored by `scoreThroughTurn` on `bookingCalls`. A tool-level mutation moves the first; a turn-boundary mutation moves the other two; nothing single-point moves both. Two mutations applied together is not "a mutation form". **The threshold was NOT changed. It stands at 3 and it is met.**

**En route, a SAFETY finding, and it is the more important half of condition 3.** Testing the strongest honest candidate mutation — `create_booking.execute` widened to really POST `/api/v1/bookings` through `clients.booking` — a **real booking call fired and both through-turn cases still scored PASS**. The cause: `scoreThroughTurn` builds two stub-client instances and watches the wrong one. `makeStubClients()` at `score.ts:204` supplies the *tool* clients and its `calls` array is discarded; `bookingCalls` at `:205` comes from `makeStubGate()`, which builds its own clients internally (`stubGate.ts:25`) and hands only `clients.booking` to the gate. So a booking side-effect made by a *tool* is invisible to the C4 through-turn assertion, which has therefore never been falsifiable against that failure mode. `stubClients.ts` claimed the opposite in its own header comment; the false comment was corrected in the same commit.

**Scope, stated precisely because a safety finding without limits is its own false claim:** this is a gap in what the eval can OBSERVE, **not an open execution path**. `create_booking.execute` omits `clients` by construction (the mutation had to widen the signature — a visible diff, not a runtime reachability), and `services/agent/test/gate/boundary.test.ts` independently blocks the executor by static import graph, **verified 3/3 passing** and untouched by any of this. Carried as open item 2, with the fix order fixed and the scorer deliberately NOT fixed in this PR: changing what a tier measures after seeing a pre-registered number missed is fitting at the tier level.
