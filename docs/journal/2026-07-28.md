## The defect, stated precisely
`shipmentJsonSchema` used `exclusiveMinimum` on `weight_kg`/`volume_cbm`. Gemini's function-declaration `Schema` proto is an OpenAPI-3.0 SUBSET, so an **unknown field name is a deterministic JSON→proto parse rejection → non-retryable 400**, and the fallback allowlist is 429/5xx/timeout/network ONLY (ADR-0006/L1) — so there is no retry and no recovery. Consequence: **every real full-`TOOLS` turn against the PRIMARY died**, the router fell through to Groq, and all 30 committed L6 fixtures were captured from the **FALLBACK** — while the suite reported a confident green baseline for a chain whose primary could not serve a single request. The mechanism was the keyword; the DEFECT was that the rejection was INVISIBLE.

## Shipped
1. **The fix (one line of production schema):** `exclusiveMinimum: 0` → `minimum: 0` on `weight_kg` and `volume_cbm`, with the strict ">0" intent moved into `description` (the text the model actually reads). **Zod `cargoSchema` keeps `.gt(0)`, unchanged** — it remains the enforcement boundary. The model-facing hint is now DELIBERATELY WEAKER than the rule; that asymmetry is intentional and is now pinned by a test so the obvious "align them" cleanup can't land green.
2. **`test/tools/geminiSchemaCompat.test.ts` (agent) — mechanism guard.** Walks the SAME object graph `geminiProvider.ts` spreads into the request and fails the build on any field name outside Gemini's `Schema` allowlist (`exclusiveMinimum`, `multipleOf`, `additionalProperties`, `$ref`, `oneOf`, `allOf`, `const`, …). DB-free, live-call-free.
3. **`test/tools/cargoBounds.test.ts` (agent) — boundary guard.** Asserts Zod rejects `weight_kg: 0` (the value the JSON hint now admits), that the hint says `minimum: 0` with no `exclusiveMinimum`, and that the lost intent survives in `description`.
4. **`evals/runner/test/recordingProvenance.test.ts` — SYMPTOM guard, the durable one.** Every committed recording must name the declared PRIMARY (`gemini`), the set must be single-provider, and every non-error recording must name its model. Error envelopes are NOT exempt (a recorded Groq error is exactly how a fallback-served fixture re-enters the set). Deliberately hardcodes the expectation instead of reading `LLM_CHAIN` — an env-derived expectation would follow a mis-pointed capture straight into a green run.
5. **All 30 fixtures re-recorded against Gemini-primary**, plus record-mode inter-case pacing (`EVAL_RECORD_DELAY_MS`) so a capture run doesn't 429 itself onto the fallback. New scorecard `evals/results/2026-07-28_v0-none.json`. **`prompt_version` stays `v0-none`** — L5 bumps it.
6. **CI now runs the runner's unit tests** (`cd evals/runner && pnpm test`) — see "the guard that couldn't gate" below.
7. **ADR-0007's live-verified chain propagated into stale config:** `.env.example`, `docker-compose.yml`, `services/agent/.env.example`, and `config.ts` (docstring + the operator-facing `ConfigError` string). Partially closes the long-carried "orphaned ADR-0007 backfill" item.

## Learned
- LEARNING.md appended ×3: (1) **LLM Engineering** — a provider's tool-schema dialect is an OpenAPI SUBSET, so an unknown KEYWORD is a hard non-retryable 400; keep the model-facing hint deliberately weaker than the validator and carry the lost constraint in `description`.
