## The defect, stated precisely
`shipmentJsonSchema` used `exclusiveMinimum` on `weight_kg`/`volume_cbm`. Gemini's function-declaration `Schema` proto is an OpenAPI-3.0 SUBSET, so an **unknown field name is a deterministic JSON→proto parse rejection → non-retryable 400**, and the fallback allowlist is 429/5xx/timeout/network ONLY (ADR-0006/L1) — so there is no retry and no recovery. Consequence: **every real full-`TOOLS` turn against the PRIMARY died**, the router fell through to Groq, and all 30 committed L6 fixtures were captured from the **FALLBACK** — while the suite reported a confident green baseline for a chain whose primary could not serve a single request. The mechanism was the keyword; the DEFECT was that the rejection was INVISIBLE.

## Shipped
1. **The fix (one line of production schema):** `exclusiveMinimum: 0` → `minimum: 0` on `weight_kg` and `volume_cbm`, with the strict ">0" intent moved into `description` (the text the model actually reads). **Zod `cargoSchema` keeps `.gt(0)`, unchanged** — it remains the enforcement boundary. The model-facing hint is now DELIBERATELY WEAKER than the rule; that asymmetry is intentional and is now pinned by a test so the obvious "align them" cleanup can't land green.
2. **`test/tools/geminiSchemaCompat.test.ts` (agent) — mechanism guard.** Walks the SAME object graph `geminiProvider.ts` spreads into the request and fails the build on any field name outside Gemini's `Schema` allowlist (`exclusiveMinimum`, `multipleOf`, `additionalProperties`, `$ref`, `oneOf`, `allOf`, `const`, …). DB-free, live-call-free.
3. **`test/tools/cargoBounds.test.ts` (agent) — boundary guard.** Asserts Zod rejects `weight_kg: 0` (the value the JSON hint now admits), that the hint says `minimum: 0` with no `exclusiveMinimum`, and that the lost intent survives in `description`.
4. **`evals/runner/test/recordingProvenance.test.ts` — SYMPTOM guard, the durable one.** Every committed recording must name the declared PRIMARY (`gemini`), the set must be single-provider, and every non-error recording must name its model. Error envelopes are NOT exempt (a recorded Groq error is exactly how a fallback-served fixture re-enters the set). Deliberately hardcodes the expectation instead of reading `LLM_CHAIN` — an env-derived expectation would follow a mis-pointed capture straight into a green run.
5. **All 30 fixtures re-recorded against Gemini-primary**, plus record-mode inter-case pacing (`EVAL_RECORD_DELAY_MS`) so a capture run doesn't 429 itself onto the fallback. New scorecard `evals/results/2026-07-28_v0-none.json`. **`prompt_version` stays `v0-none`** — L5 bumps it.
6. **CI now runs the runner's unit tests** (`cd evals/runner && pnpm test`) — see "the guard that couldn't gate" below.
7. **ADR-0007's live-verified chain propagated into stale config:** `.env.example`, `docker-compose.yml`, `services/agent/.env.example`, and `config.ts` (docstring + the operator-facing `ConfigError` string). # Session 2 — L5 PR A: prompt composition seam + scorer fix

**Phase/Layer:** Phase 2 / **L5, PR A of a deliberate two-PR split**. HERMETIC — no live LLM calls, no capture, `prompt_version` stays `v0-none`. NOT a phase exit; NOT the prompt PR. Staged, uncommitted (the user runs all git), on top of PR #21.
**Session goal:** build the seam the prompt will travel through, and fix the scorer that would have measured it, BEFORE authoring a single line of prompt.

## Why L5 is two PRs (architecture-guardian ruling)
The guardian was consulted on how to sequence L5 and **ruled for a two-PR split** (its original split; a single-PR plan and a variant split were both rejected). The reasoning is a confound argument: PR B's extraction number will move for **three independent reasons** — a stricter scorer, new hard cases, and a real prompt — and the pre-registered floor gets applied to *that* number. Isolating the scorer change in PR A means PR B carries only the unavoidable cases+prompt confound instead of three. The same ruling also held that **85% is superseded** (its replacement is ADR-0012, which belongs to PR B) and that **ADR-0011 finding (b) is CUT from L5** and ships as its own PR with its own ADR.

## The hazard this PR closes — guardian H1
There were **two message-composition sites**: `turnService.ts` built its own `[{role:"user"}]` array, and the eval runner's `toMessages()` built one from case YAML. And **30 of the suite's 31 cases drive `runAgentTurn` directly, not `runTurn`.** So adding a system prompt to production alone would have left nearly the whole suite replaying the **PROMPTLESS** path while its scorecard carried the new `prompt_version` — a label decoupled from the bytes. That is the same defect class as ADR-0011 finding (a), which is exactly the failure this project has already paid for once.

## Shipped
- **`services/agent/src/prompt/systemPrompt.ts` (new)** — `composeMessages(systemPrompt, conversation)`, PURE, with the prompt as a **parameter** so it is testable with no prompt file in existence; `SYSTEM_PROMPT` (`undefined` at v0-none, typed `string | undefined` so the prompted branch stays reachable to the type checker); `PROMPT_VERSION` (condition **C3** — agent-service OWNS it).
- **Both paths route through it (C1):** `turnService.ts` and `evals/runner/src/score.ts#toMessages`. `evals/runner/src/promptVersion.ts` now **re-exports** rather than holding a second literal — two constants can drift, and a scorecard saying `v1` while the service ships `v2` is finding (a) again.
- **Scorer fix (ruling 2):** `scoreText` fails on an empty/whitespace answer; `text_contains` is REQUIRED and non-empty at the **SCHEMA** level; `contains` is typed `string[]` (not `| undefined`) so a schema regression becomes a **compile error** rather than a scorer that silently asserts nothing.
- **`role: "system"` removed from the case `messageSchema`** (security-reviewer's Medium) — a case-authored system turn would, once `SYSTEM_PROMPT` is non-empty, produce a two-system-message list production can never emit, and could neutralize the production prompt while the scorecard still stamped `v1`.
- **New guards:** `evals/runner/test/fixtureCompleteness.test.ts` (C9 amended), `evals/runner/test/composerSeam.test.ts`, `evals/runner/test/composerSeamMocked.test.ts`, `services/agent/test/prompt/promptReachesTurn.test.ts`, `services/agent/test/prompt/systemPrompt.test.ts`.
- 3 clarify cases gained `text_contains`; new scorecard **`evals/results/2026-07-29_v0-none.json`**.
- Guardian conditions closed: **C1, C2a, C3, C9 (amended), C20**, plus ruling 2's scorer + case-schema fix.

## The three things worth remembering from this session

### 1. H7 — an eval-gaming surface that is invisible to artifact forensics
On the previous PR, eval-auditor **positively excluded** gaming by recomputing all 31 recording keys under the old and new tool schemas and showing every old key mapped to a deleted fixture and every new key to an added one: the churn was **structurally forced**, so cherry-picking was impossible. **That technique does not transfer to expectation-only edits.** `recordingKey` hashes `{prompt_version, messages, tools}` and **ignores the `expect` block entirely** — so this PR edited three cases' expectations with **ZERO fixture churn**. `text_contains` substrings could in principle have been fitted to known recorded outputs, leaving no fingerprint at all.

Record BOTH halves, in the auditor's own framing:
- **The finding:** expectation-only edits are **unauditable by fixture churn**; per-substring justification is the only evidence available.
- **The limitation:** the auditor's three arguments for THIS PR — (a) the `weight` needle was applied to a case whose fixture cannot exercise it, so there was no recorded text to fit to; (b) the **weakest** available needles were chosen when far more distinctive strings (`5-letter UN/LOCODE`, `on Earth`, `port`) were on offer; (c) the rule was stated once up front and applied uniformly — are **consistent with** rule-derivation but do **NOT exclude** a careful fitter, who would pick generic needles precisely because they look principled.
- **The honest summary:** this class of change is auditable by **coherence, not by artifact**. The mitigation is **procedural** — state the rule before reading outputs, apply it uniformly including where it hurts — and is **trust-based, not proof-based**. Do not compress this to "expectation edits are unauditable"; the limitation is half the lesson.

### 2. A guard that only arms once the hazard is realised is absent for exactly the window in which the mistake gets made
eval-auditor's Blocking B1: the seam tests were **TAUTOLOGICAL at `v0-none`**. Since `composeMessages(undefined, x) ≡ [...x]`, every `expect(driven).toEqual(composeMessages(SYSTEM_PROMPT, conv))` passed equally against a hand-built array. Proven by **reverting BOTH call sites**: all eleven seam tests stayed green.

code-reviewer had seen the same tautology and classified it **non-blocking** ("test gap") on the reasoning that the tests self-arm once `SYSTEM_PROMPT` is non-empty. True — and beside the point: **the gap and the hazard share the same window.** H1 is the risk that a prompt reaches production without reaching the thing measuring production, so a guard that arms only once the prompt exists is missing **precisely when it is needed**. The main session accepted code-reviewer's classification initially and was **overridden by eval-auditor**.

Fixed by **mocking `SYSTEM_PROMPT` to a sentinel while keeping the REAL composer in the path** (`composerSeamMocked.test.ts`) — falsifiable today, with no prompt file. Verified by re-running the mutation: **1 failure in agent-service, 3 in the runner**, both restored clean.

### 3. A predicted regression that did NOT occur — and why not writing the disclosure was the right call
Guardian condition **C20** required disclosing an expected extraction-number **DROP** (the stricter scorer flipping clarify cases to FAIL). **It did not happen.** Extraction held at **14/15 (0.9333)**, and the new scorecard is **byte-identical to `2026-07-28_v0-none.json` as a whole file** — `cmp evals/results/2026-07-28_v0-none.json evals/results/2026-07-29_v0-none.json` exits 0. The recorded promptless answers already satisfied the product-derived needles substantively — "I'll need a destination port… Could you please specify your destination port?" and "Please provide a valid origin location on Earth". eval-auditor **mutation-tested** the needles (swapping in an absent string flips both cases to FAIL), confirming they are live rather than hollow.

So **C20's disclosure text was NOT written**, because it would have described a correction-vs-regression distinction for a change that did not occur. The byte-identity is not a curiosity — it is the **evidence**: the scorecard body deliberately carries **no timestamp**, which is exactly what makes `cmp` a machine-checkable proof that nothing moved, stronger than any prose claim. That is also why committing an apparently redundant scorecard is right rather than noise — it is the artifact a future reader diffs.
